# TRITIUM — F8 · v0.1.8 · «Charts»

Repo path of this file: `~/REPO/build/docs/F8.md`
Governing document: `~/REPO/XTRITIUM.md` — where this file and XTRITIUM disagree, XTRITIUM wins.

Seven charts, named in XTRITIUM §7.2 and not negotiable: **Fuel Consumption ·
Monthly Costs · Gas Price · Fill-up Costs · Odometer · Cost per Kilometer ·
Monthly Distance.**

F7 built the range chips and proved, in a test, that a filter applied before a
derived figure destroys it. F8 puts seven derived figures behind the same chips.
Everything F7 was careful about, F8 is careful about seven times over.

There are three collisions with rules the project has already made, and none of
them is resolved by quietly ignoring a rule:

- §7.2 grants every chart a **tooltip**. F4b's standing layout law, enforced by
  `audit-overlap`, is that nothing may overlap anything. See decision 2.
- §8 puts **every colour** in `palettes.css`, and `audit-colours` scans `.ts` as
  well as `.css`. A charting library wants colours as JavaScript values. See
  decision 3.
- §7 gives each chart a **fullscreen button**, and a thing that goes fullscreen
  is conventionally a thing that covers other things. See decision 4.

## 2. SCOPE — IN

### 2.1 The decisions this milestone settles

1. **A chart is a view of realised data and computes nothing new.** Every series
   is a pure function of what is in the files, in `src/shared/series.ts`, unit
   tested away from any canvas. No trend line, no regression, no forecast — §3.3
   forbids projecting entries the maker did not make, and a fitted line through a
   fuel log is exactly that wearing a lab coat. §7.2 adds one more by name:
   **no average reference line.**

2. **Charts get a tooltip, and the layout law is not weakened to allow it.**
   §7.2 grants it explicitly, and where §7.2 and a milestone's implementation
   rule disagree, XTRITIUM wins.

   The two rules are about different things, which is why both survive. F4b's law
   is about the application's own chrome: no menu over a table, no dialog over a
   form, no popover anchored to a control. A chart tooltip is a **reading aid
   inside one canvas**, it exists only while the pointer is inside that canvas,
   and it covers only the plot it belongs to.

   `audit-overlap` is not relaxed. It scans `src/`, and the exemption is written
   **into the audit's own header comment**, in the open, next to the rule it
   narrows — which is the mechanism that file already documents for exactly this
   case ("When a genuine need appears, the exemption is written here… the way
   audit-colours exempts palettes.css by name"). No `role="tooltip"` is written
   anywhere; ECharts is configured through an option object.

3. **Chart colours are read from the cascade, not written in TypeScript.**
   `audit-colours` scans `.ts` and `.tsx`, so a hex in a chart option is a build
   failure — correctly, because §8 says every colour is a custom property in
   `palettes.css`.

   So the chart reads its colours **out of the live document** with
   `getComputedStyle`, from the `--accent-seq-1 … --accent-seq-8` tokens F4b
   defined for exactly this and the text/border tokens for the axes. The
   consequence is the good one: **switching palette re-colours every chart
   instantly**, because the charts were never holding a colour of their own. The
   eleven palettes keep their promise on this tab too.

4. **Fullscreen replaces; it does not cover.** §7's per-chart fullscreen button
   is honoured by the chart taking over the whole two-pane region — the grid of
   seven is replaced by the one, in normal flow, with the button becoming its
   own inverse. Nothing is painted over anything, so `audit-overlap` has nothing
   to say and the law holds without an exemption.

   A real `requestFullscreen` is deliberately not used: it takes the window away
   from the compositor that §7 says draws the decorations.

5. **The range decides the window; the engine still sees everything.** F7's
   decision 3, restated because it is now seven times as easy to get wrong. The
   consumption series in particular is computed from `bundle.fuel.entries` entire
   and filtered afterwards — filtering first silently loses the points whose
   earlier full tank fell outside the window, and produces a chart that is wrong
   in a way that looks like data. `tests/unit/range.test.ts` already pins the
   hazard; F8 adds the same assertion for the series.

6. **Two granularities, and each chart says which it is.** Four charts have a
   point per record — Consumption, Gas Price, Fill-up Costs, Odometer. Three are
   **monthly aggregates** — Monthly Costs, Monthly Distance, Cost per Kilometer.
   Mixing them silently is how a reader concludes the car cost forty lira in
   March.

7. **Monthly Costs is every lira the vehicle cost that month.** Fuel, costs and
   service together, from all three files, with `income = true` entries
   subtracting (§4.4). The alternative — non-fuel only — would make the chart
   disagree with the Summary card §7.1 asks for and with the cost-per-km figure
   beside it. **Fill-up Costs stays separate and is not a monthly figure**: it is
   the cost of each individual fill-up, which is a different question and is why
   §7.2 lists both.

8. **Monthly Distance is measured between the readings that exist.** A month's
   distance is the highest odometer known by the end of it minus the highest
   known before it. A month with no reading produces **no bar** rather than a
   zero: zero kilometres and no record of driving are different claims, and only
   one of them is in the file (§3.3).

9. **Cost per Kilometer is monthly, and only where both halves are real.** Spend
   in the month ÷ distance in the month. A month with spend but no distance
   produces no point — dividing by an unknown is a guess, and the app that
   targets precision does not guess (§5.2).

10. **Bar charts carry a data table beneath**, per §7.2 — the three monthly ones.
    It is the same `.entries` treatment the lists wear, so a figure read off the
    chart and the same figure read off the table cannot render differently.

11. **Line, area and smooth are per chart and not remembered.** §7.2 asks for the
    toggles. They are a way of looking at the chart in front of you, not a
    setting: `settings.toml` gains nothing, F11 inherits nothing, and the file
    stays the record of the vehicle rather than of how the maker likes his lines.

12. **Zoom and pan come from the data-zoom component, inside the plot.** §7.2
    asks for both. They move the view within the chosen range; the chips remain
    what decides which records exist at all.

### 2.2 The series — `src/shared/series.ts`

Seven functions, each taking the records it needs and returning `{ x, y }` pairs
with `y` in scaled integers (§4.3). No formatting, no colour, no ECharts type
crosses into this file — it is arithmetic, and it is tested as arithmetic.

Month keys are built from the `YYYY-MM-DD` strings directly (`slice(0, 7)`),
never by constructing a `Date` — the same reasoning `range.ts` gives, and the
same reason `todayIso` exists (§3.6, and F4's UTC+3 trap).

### 2.3 The chart — `src/renderer/panes/Chart.tsx`

One wrapper around `echarts/core`: it builds an instance on mount, disposes it on
unmount, resizes with its container, re-reads the palette when the palette
changes, and takes an option object from its caller. Nothing else in the renderer
touches ECharts.

### 2.4 Tests that must exist

- **vitest:** each of the seven series against hand-worked figures — including a
  month with spend and no distance producing no cost-per-km point, a month with
  no reading producing no distance bar, and an income entry subtracting from a
  monthly total · month keys taken from the string and not from a `Date` · **the
  consumption series over a filtered view equalling the series over the whole
  history**, which is F7's hazard in its new home.
- **Playwright:** all seven charts render a canvas · the chips change what is
  plotted · a palette switch re-colours a chart without a reload · fullscreen
  replaces the grid and returns · a bar chart shows its data table · the line /
  area / smooth toggle changes the series type · **no `<a>` anywhere, still** ·
  all of it with the network severed.

## 4. ACCEPTANCE CRITERIA

F8 is done when every line below is true:

1. `npm test` is green: the five audits, both tsconfigs silent under `strict`,
   the units, the build, and the e2e suite.
2. All seven charts of §7.2 exist, each with the chips, a custom range, zoom, pan
   and a fullscreen button.
3. **No colour literal exists outside `palettes.css`** — the charts take their
   colours from the cascade, and a palette switch re-colours them at once.
4. A consumption figure plotted is identical whether or not the chip hides the
   entry it was measured against.
5. A month with no odometer reading produces no distance bar; a month with no
   distance produces no cost-per-kilometre point.
6. Fullscreen replaces the grid in normal flow — `audit-overlap` passes, and
   nothing is painted over anything.
7. Every figure and axis label is in the family convention — `1.234,56 ₺`,
   `GG/AA/YYYY` — in both languages, with no `Intl` call and no locale read.
8. The three monthly charts carry a data table beneath, agreeing with the plot.
9. No average reference line, no trend line, no projection anywhere.
10. Zero network: the audits still prove it statically and the offline e2e run
    still behaves identically.
11. No AI attribution exists anywhere in the tree or the git history.
