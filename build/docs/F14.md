## 2. SCOPE — IN

### 2.1 The decisions this milestone settles

1. **The README is §10's, to the letter.** Banner, badges, bilingual subtitle,
   numbered ALL-CAPS sections — DESCRIPTION, DEPENDENCIES, INSTALLATION, HOW TO
   USE, LICENCE SUMMARY — and "Built with Reason and Passion." at the end. §10
   names the sections; F14 does not add one or reorder them.

2. **The subtitle is the one already in the application, in both languages.**
   §11.4 reserved the wording, and the wording has in fact existed since F1:
   `app.subtitle` reads *"Fuel Logging / Maintenance Tracking for any ICE
   Vehicle"* and *"Her İçten Yanmalı Araç için Yakıt Kaydı / Bakım Takibi"*.

   Inventing a new one for the README would put the badge on the box at odds
   with the label inside it. **If the maker wants different words, changing them
   in `en.json` and `tr.json` changes them everywhere, and the README should be
   brought to match — not the other way round.**

3. **The badges carry measured figures, and the one that cannot be measured says
   so.** §10 asks for version, release date, licence and **Arch package size**.
   The first three are facts this repository holds. The fourth cannot be known
   until the package is built in a clean chroot, which is the maker's step
   (F13.md §4).

   So it is measured as closely as it honestly can be and labelled as an
   estimate: the unpacked tree is **398 MB installed**, and the same tree
   compressed at makepkg's own zstd setting is **~136 MiB**. The badge carries
   that figure with a `~`, and `packaging/README.md` says where the real number
   comes from. A confident wrong number on a badge is worse than an honest
   approximate one.

4. **The About page and the README state the same version, and a test already
   holds it.** `tests/unit/app-meta.test.ts` binds `APP_VERSION` to
   `package.json` and to both places the lockfile says it. The README badge is
   the fifth copy, and it is the one nothing can check — so it is written to be
   changed at the same moment as the other four, and the release procedure in
   `packaging/README.md` says so.

5. **`PUTAGREL` is not F14's to perform.** §9.2 gives it to the maker's signal
   and it means *push and release* — the first thing in this project's whole
   protocol that leaves the machine. F14 ends where every other milestone ended:
   committed and tagged locally, with nothing pushed.

6. **The final sweep changes behaviour only where something is wrong.** A
   milestone called Polish is where a project acquires unnecessary changes. If
   the sweep finds a defect it is fixed and recorded in `issues.md`; if it finds
   something merely not to taste, it is left alone.
