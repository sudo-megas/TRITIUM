# AF12 — TRITIUM Android · «Codebase audit»

## Context

AF11 shipped and enrolled-tested the first real, signed Android release.
Before the maker's own final decision — flipping that release from
Pre-release to Release — the maker's own roadmap asked for one more thing:
a hard-capped, multi-lens audit of the whole Android codebase, and every
finding fixed regardless of severity, no triage by criticality.

## §1 THE AUDIT

Run via the `Workflow` tool, exactly five agents — the maker's own explicit
resource cap, honoured literally rather than as a target:

| Agent | Model / effort | Lens |
|---|---|---|
| 1 | Opus 5, xhigh | Data integrity — storage layer: scaling, TOML round-trips, skip-wins merge, backup-before-write |
| 2 | Opus 5, xhigh | Security — the zero-permission/zero-network contract, SAF usage, signing hygiene |
| 3 | Sonnet 5, xhigh | UI/ViewModel correctness — StateFlow, Compose lifecycle, main-thread I/O |
| 4 | Sonnet 5, xhigh | Cross-platform parity with the desktop, and AF-doc accuracy against the current code |
| 5 | Haiku 4.5, high (the maker's own "Extended" effort has no literal equivalent in this harness's effort enum — mapped to `high`, flagged here for correction) | Hygiene — dead code, unused imports, hardcoded strings, resource leaks |

No further agent fan-out: verification and fixing happened in the
orchestrating session's own context, not via additional agents, to respect
the cap. 18 findings returned, all independently re-verified against the
actual code before being counted as real — 1 critical, 5 high, 7 medium,
5 low. Zero were false positives; all 18 were fixed.

## §2 THE FINDINGS AND THEIR FIXES

**Data integrity:**
1. **Gallon round-trip precision loss** (Units.kt/UnitFormat.kt, both
   platforms) — volume shown in gallons carried no extra decimal the way
   `DISTANCE_DECIMALS` already gives miles over kilometres, failing the
   round trip for the large majority of realistic values. Fixed with a
   `VOLUME_DECIMALS` map and the same `×10`/`÷10` shift `showDistance`/
   `readDistance` already use — exact for the full range on both platforms
   now, proven by an exhaustive test.
2. **Export aborts on one bad vehicle** (SettingsViewModel.kt) —
   `exportBundle` parsed every vehicle's four files eagerly; one corrupt
   file anywhere aborted the whole export, the only way data leaves the
   device without root. Now skips the one unreadable vehicle.
3. **Duplicate slug in a bundle loses entries** (VehicleRepository.kt,
   import.ts) — two `[[vehicle]]` tables sharing a slug were planned
   independently against the same on-disk state; the second write silently
   overwrote the first's entries while the report counted them as added.
   Repeated slugs now merge into one plan, threading documents and id
   allocation forward.
4. **`saveVehicle` crashes on an unrelated corrupt file** (HomeViewModel.kt)
   — recovering the existing record's carried keys read all four files;
   a corrupt fuel/costs/service file crashed a rename. New
   `loadVehicleRecord` reads only `vehicle.toml`.
5. **`settings.toml` drops unknown keys** (ConfigStore.kt) — the typed
   decode/encode round trip discarded anything this build does not model
   on the next save, unlike every record file and the desktop's own
   `settings-file.ts`. Fixed via tomlkt's document model, additive: the
   common no-unknown-keys path is byte-identical to before.
6. **Duplicate entry id kept verbatim** (EntryFile.kt, entry-file.ts) — a
   hand-edited duplicate id was never re-allocated, corrupting
   `entryRest` and making delete/update touch two entries at once. Now
   re-allocated the same way a missing id already was.

**Security:**
7. **Path traversal via a bundle's slug** (VehicleRepository.kt,
   import.ts) — a slug containing `..`/`/` was used verbatim as a
   directory name. Refused outright unless the slug already equals its
   own `slugify()` output.
8. **emoji2's network-capable initializer** (AndroidManifest.xml) — a
   transitive dependency asks a downloadable-font provider for the emoji
   font on first cold start, a network fetch on this app's behalf that
   `aapt dump permissions` cannot see. Removed via `tools:node="remove"`.
9. **Root `.gitignore` gap** — `android/.gitignore` excluded signing
   material, but a keystore generated at the repo root (a natural cwd)
   was not covered. Added.

**UI/ViewModel:**
10. **CRITICAL — silent edit loss on a stale ViewModel** (Fuel/Cost/
    ServiceViewModel, all three form screens) — the form's edit-mode load
    read a StateFlow snapshot that could be empty after process death;
    the form then saved under an empty id, wrote nothing, and reported
    success anyway. Now a one-off repository read per lookup; the forms
    also check the save's own result before navigating away.
11. **Silent no-op delete** (Fuel/Cost/ServiceScreen) — confirming a
    delete on an id already gone was indistinguishable from a real
    delete. Now surfaced with a failure message.
12. **Main-thread I/O everywhere** — every repository read/write, export,
    import, and the About screen's licence read ran on the main thread;
    an ANR risk at the scale AF11's own enrolled test exercises. Every
    ViewModel action is now `suspend`, dispatched via
    `withContext(Dispatchers.IO)`; the four record forms needed a real
    split into a loading-gate composable and a body composable, since a
    `rememberSaveable` field seeded from a value that arrives
    asynchronously never updates.
13. **`CurrencyAskDialog` loses its answer on rotation** — `remember`
    instead of `rememberSaveable` on a dialog with no cancel button.
14. **LICENSE read on the main thread** (SettingsScreen.kt) — wrapped in
    `withContext(Dispatchers.IO)`.

**Parity and docs:**
15. **Rounding-mode divergence** (Scaled.kt + six functions in Units.kt)
    — `kotlin.math.round` compiles to `Math.rint` (ties to even); the
    desktop's own `Math.round` rounds ties up. A figure landing exactly
    on a tie scaled to a different integer per platform from the same
    TOML byte. Switched to `roundToLong()`/`roundToInt()`.
16. **AF8.md's stale `buildBundle` reference** — the real name is
    `Bundle.build`. Corrected.

**Hygiene:**
17. **Unused import** (RangeChips.kt) — removed.

**Found running the fix, not in the audit itself:** converting every
ViewModel action to `suspend` surfaced a real crash the instrumented
suite alone caught — `withContext(Dispatchers.IO)` restoring the
caller's own dispatcher on return cannot be assumed to land back on the
genuine Android main thread under this project's own test harness, and
`popBackStack()`'s internal `LifecycleRegistry.setCurrentState` asserts
exactly that. Fixed with an explicit `withContext(Dispatchers.Main.immediate)`
around every post-save navigation call, in all five form screens.

## §3 VERIFICATION

`./gradlew check` green after every fix. The full instrumented suite —
all eight classes — run on the connected device, `pm clear` between each
for isolation: seven green. `CostFlowTest` failed on its own
already-documented, pre-existing IME-timing flakiness on this specific
device (present before AF12, unrelated to any of the 18 fixes) — its own
header comment states manual verification is the real acceptance gate,
not this test's pass/fail on a given run. Both scenarios it covers
(a picked İLK ALIŞ category, a typed MANUAL category slugified on save,
the income checkbox flipping only the displayed sign) were independently
confirmed correct by hand, on-device, disk state read directly.

Desktop: `npm run typecheck` and the full unit suite (357 tests) green.
The full Playwright/Electron e2e suite could not run in this session —
the background job's own context cannot reach the X server the maker's
live desktop session uses, confirmed directly (`xdpyinfo` fails to
connect) rather than assumed. Not a code signal either way; the desktop
changes (units.ts, fuel-draft.ts, import.ts, slug.ts, entry-file.ts) are
covered by the unit suite, including new exhaustive round-trip tests.

## §4 EXIT

Every finding fixed — the 2.b branch of the maker's own roadmap: the
`android-v1.0` pre-release stands untouched, and a new `android-v1.1`
pre-release follows this doc, carrying every fix above. Final phone
cleanup happens after that release is verified.
